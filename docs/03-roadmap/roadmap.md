# Roadmap

> **Revision note (2026-08-20):** The GDD dropped Karate Bout and the multi-Chao autochess board in favor of a single-Chao 24-entrant Tournament bracket, with Breeding now a core mechanic. Phases 0 and 1 below are historical fact (already built, still valid) and untouched. Everything from Phase 2 onward is **rewritten** to match the new direction — the old Phase 2 ("run structure": node map), Phase 3 ("autochess layer": board/Fruit/Species-Tag breakpoints), and part of Phase 5 (breeding as a stretch item) no longer describe where this project is going. See [`game-design-document.md`](../01-design/game-design-document.md)'s own revision note for the full design rationale.

## Sequencing principle

The original risk still applies in spirit, just aimed at a different stack of layers: Race mechanics, the Tournament bracket, Environment Interludes, and Breeding are each their own system, and stacking all of them before any is played risks the same "overwhelming, can't tell what's working" failure mode the original sequencing principle was written to avoid. So the build order below is still **layered, not featured-complete-per-system**: get the bracket working end-to-end with no Environment/Breeding first, then add Environment, then add Breeding — each playable and evaluable before the next layer stacks on.

- [x] Authored a handful of Climb (Black: Boulder Ram, Sheer Face Crawler, Quarry Grip Tonic) and Jump (Red: Spring-Heel Hare, Cliffhopper Goat, Bounding Draught) cards — proposed color mapping (Climb→Black, Jump→Red) per GDD §3.2, not locked.
- [x] Card-data audit: Bout-only-triggered keywords/effects (`bout_start`/`round_start`/`on_hit`/`on_dodge`) are left dormant with the reasoning now documented centrally in `types.ts`'s `TriggerCondition`/`EffectOp` doc comments, rather than touching every individual card — they were already silently inert under the Race resolver (it never checks those trigger kinds), so no behavior changed, only the explanation of *why* that's intentional.

## Phase 2.5 — Fix the Bond Card model (cumulative, multi-region, mixed-sign) *(complete, 2026-08-20)*

**Blocked Phase 3** — a Tournament needs Chao whose stats actually work correctly. Corrects a real bug in the original design and its Phase 0 implementation, caught 2026-08-20 (GDD §3.5): Bond Cards were modeled as 4 exclusive slots where bonding a new card *deleted* the old one. The real mechanic is cumulative — any number of cards, each possibly touching multiple Body Regions with a mix of positive and negative stat grants, all stacking, never replacing.

- [x] `types.ts`: renamed `BondSlot` → `BodyRegion` with 5 values, **locked 2026-08-20**: **Legs, Arms, Back, Head, Torso**. `StatGrant` gains an optional `region: BodyRegion` field and supports negative `min`/`max`. `BondCard` drops its single `slot` field; gains `bodyMutations: Partial<Record<BodyRegion, string>>` so one card can carry a cosmetic mutation per region it touches.
- [x] `Chao`: replaced `bondSlots: Partial<Record<BondSlot, BondedCard>>` (4-slot exclusive record) with an unbounded, append-only history, `bondedCards: BondedCard[]`. `BondedCard.rolledGrants` entries carry their region tag through from the `StatGrant` they were rolled from.
- [x] `chao/bonding.ts`'s `bondCard()`: removed all "check occupied slot → reverse previous card's contribution → replace" logic. New behavior: rolls each grant (respecting sign), accumulates onto `chao.stats`, appends the `BondedCard` to the history — full stop. `BondResult` no longer has `replacedCard` (nothing is ever replaced anymore).
- [x] `chao/derived.ts`'s `recomputeDerived()`: color identity / alignment / species tag counts now fold over the full `bondedCards` history instead of `Object.values(bondSlots)`. New derived field `regionLooks` implements **discrete top-contributor-wins**: per region, tallies Species Tag contributions from every bonded card that touched it, and whichever tag has the highest count determines that region's `bodyMutation` asset (a simple count/max, not a rendered blend — see GDD §3.5 for why a true proportional blend is explicitly deferred).
- [x] New `EffectOp` variant for special traversal/shortcut cards, `grantAlternateRoute` (`legType` + `description` fields) — not yet consumed by any resolver or authored onto any card; the type exists for future shortcut-ability cards (the Elephant "walks the riverbed instead of swimming" example) to use.
- [x] Migrated all 5 color files (`packages/sim/src/cards/data/{green,red,black,blue,white}.ts`, 91 cards total including non-Bond types) to the new shape — mechanical schema migration (per-grant region tags, `bodyMutations` records), not a content redesign. The multi-region mixed-sign "Penguin" content pass remains a tracked follow-up (see below) — every migrated Bond Card still grants only positive stats from the single region it always touched.
- [x] `GardenScreen.tsx`: replaced the 4-slot "Bond Slots" list with a "Body Regions" summary (5 regions, each showing `chao.regionLooks[region]` or "unmarked") plus a scrollable "Bonding History" list (`chao.bondedCards`, own `.bonding-history-list` CSS class — initially miscoded to reuse `.event-log`'s class, colliding with the real Event Log column; caught during Playwright verification and fixed).
- [x] Updated every test that referenced `bondSlots`/`BondSlot`/`replacedCard`/`card.slot`: `chao/bonding.test.ts` (including turning the old "replaces the previous card" test into an "accumulates onto a second bonded card" test), `draft/bots.test.ts`'s `makeBondCard()` helper, and stale comments in `events/race.test.ts`. `events/shared.test.ts` and `cards/coreGardenSet.test.ts` needed no changes.
- [ ] **Content follow-up, tracked separately, not part of this phase's "done":** re-author Uncommon+ cards to actually carry the full multi-region, mixed-sign pattern (most currently only grant 1-2 positive stats on a single region) — a real design/balance pass, not a mechanical migration. Commons stay simple per the rarity-gated-complexity decision (still flagged as a TODO to reconsider, see open questions).

**Done when:** ✅ Met — `pnpm build`/`typecheck`/`test` all green (72 sim tests, all passing) against the new model; verified live via Playwright that a Chao can bond the same card twice with the Bonding History count growing (2, not replaced), the affected region's look updates, stats accumulate, race narration reads cleanly with no `[object Object]`, and no console errors.

## Phase 3 — Tournament bracket core loop *(complete, 2026-08-20)*

The bracket itself, with no Environment Interludes or Breeding yet — just prove 24 entrants can play down to a ranked Final Race.

- [x] New `packages/sim/src/tournament/` module (architecture.md §5.5), split across `entrants.ts` (entrant gen + scouting), `fieldRace.ts` (rank-a-field / eliminate-last-place primitives, shared by both the player's interactive group and silently-resolved off-path groups), and `bracket.ts` (the bracket state machine itself: `createTournament`, `advancePlayerGroupRace`, `runFinalRace`).
- [x] **Key structural decision, not in the original checklist:** every branch of the bracket that never touches the player's own choices (the group paired with theirs, plus the entire opposite side of the bracket) is resolved silently and eagerly at `createTournament()` time, since none of it depends on player input — only the player's own group is advanced race-by-race, interactively. This matches architecture.md §5.5's "off-path groups only need a final ranking" requirement by construction rather than by special-casing it later.
- [x] The Draft Booster, once per Tournament before Round 1 (GDD §4.5, §6.2) — unchanged, existing `draft/` module now feeds a freshly-created Chao straight into `createTournament()`.
- [x] Entrant generation **v1**: 23 non-player entrants via a procedural stat roll (`generateEntrant`) — no drafting, no bonding. Also gave entrants a small curated flavor-name pool (`generateEntrantNames`) so the bracket/standings UI reads as individuals, not `entrant-7`.
- [x] Scouting: `computeScoutingRead(chao)` buckets the 7 Leg-relevant stats into a 1–5 rating (simple fixed thresholds, explicitly not tuned — GDD §6.7 flags this as low priority).
- [x] Ranking/tiebreak rule for a multi-entrant race (a new technical question the original checklist didn't anticipate, since `resolveRace` only ever tracked one Chao): run every entrant independently through the same generated course, rank by `legsCompleted` (a DNF naturally lands wherever its distance covered places it — no separate DNF special-case needed), tiebreak on remaining Stamina, then a seeded coin-flip. **Decided 2026-08-20**; a future race-*animation* pass may want richer signals than this — tracked as a TODO, not blocking.
- [x] First/Second Evolution trigger points — **decided 2026-08-20:** the same bracket-progress milestones as the two (not-yet-built) Environment Interludes — First Evolution when the player's group first shrinks to 3 (end of Round 1), Second when it does again (end of Round 2). Implemented as `Chao.evolvedAlignment`/`evolvedColor`, frozen at that moment, independent of any later drift in the live `alignment`/color fields. The "small passive" GDD §3.4 mentions each Evolution granting is an explicit open TODO — not implemented, no number invented to fill the gap.
- [x] Confirmed: only the player's own bracket path produces visible events; off-path groups resolve to a final ranking only (see the structural decision above).
- [x] Minimal UI: `TournamentPanel.tsx` (phase banner, current-group/finalist standings with click-to-scout entrant rows, Final Race results, elimination messaging) plus an `EventLogPanel.tsx` split out of the old `GardenScreen.tsx`. Entrant inspection (click any row) shows the scouting-icon read for any of the 24, not just the player's own Chao, including ones already eliminated. `narrateSimEvent` gained an optional `nameById` map so group-race narration shows real names instead of raw chao ids.

**Done when:** ✅ Met — `pnpm build`/`typecheck`/`test` all green (89 sim tests, up from 72: +17 new across `tournament/entrants.test.ts`, `tournament/fieldRace.test.ts`, `tournament/bracket.test.ts`, including a deterministic strong-player test that drives all the way through Round 1/2/3 to the Final Race and through `runFinalRace` to a correct 1st/2nd/3rd). Verified live via Playwright across 5 full draft-to-elimination runs: the draft correctly hands off into a Tournament, bonding/consuming cards between races updates the live entrant used by the bracket engine (not a stale copy), standings/scouting/elimination UI all render correctly with real entrant names (never a raw `entrant-N` id, never `[object Object]`), and two independent round transitions (Round 1→2, Round 2→3) were observed live, including a correctly-firing First Evolution ("Evolution stage: 1 — locked hero") at the Round 1→2 boundary. Draft-luck denied Climb/Jump cards across all 5 live attempts, so the Final Race screen itself wasn't reached live within this session — that path is covered deterministically by the unit tests instead, which is an accepted gap for this milestone, not a known bug.

- [x] `Environment` state: separate from the Chao, in a new `packages/sim/src/tournament/environment.ts` — exactly 3 Habitat Slots, each generating Fruit at Tournament start + after every race (base 2/trigger, 3 at 2-star, 1 Wildcard for an empty/Open Fort slot). - [x] New `Seed` card type (`types.ts`, `cards/data/seeds.ts` — 1 per color, 5 total, common rarity): drafted from both the Draft Booster and the Environment Interlude Booster; plants into a filled Habitat Slot via `plantSeed()`. - [x] The Environment Interlude Booster (`tournament/interlude.ts`): 3 packs of 3 cards each, pick 1 per pack, no passing/bots — a small standalone mini-draft, not built on `draft/engine.ts`'s pack-passing machinery. A new `InterludeBoosterScreen.tsx` mirrors `DraftScreen.tsx`'s pattern.

- [x] Wired into the Phase 3 bracket state machine: `useGame.ts`'s `runNextGroupRace` checks `advancePlayerGroupRace`'s existing `roundJustCompleted` signal (1 or 2) and switches to the `'interlude'` phase instead of continuing straight to the next round; Round 3 → Final Race still has no Interlude, unchanged.
- [x] Splash tax (GDD §4.4) actually enforced for the first time: `bondCardWithSplashTax()` wraps the existing `bondCard()`/`computeSplashTax()` — **decided 2026-08-20: pooled (not per-color) Fruit, hard block if short.** `useGame.ts`'s `bondBondCard` now calls this instead of the plain `bondCard`, logging a clear "can't afford" message instead of silently bonding when Fruit is short.

## Phase 5 — Breeding & Tournament-to-Tournament progression *(complete, 2026-08-20)*

- [x] Breeding eligibility-pool computation (`tournament/breeding.ts`'s `computeBreedingPools`, GDD §6.4's tiered exclusion) — pure set logic over `originGroup`/`eliminatedInRound`/`finalPlacement`, fields already tracked since Phase 3 specifically for this. No new data-model work needed.
- [x] Breeding resolution (`breedChao`): `baby.stat = round(0.10 * parentA.stat + 0.10 * parentB.stat)` for every stat, flat and deterministic, no RNG. Baby otherwise starts as a fresh `createChao()`-shaped entity. Cosmetic/skill inheritance remains explicitly deferred, per the GDD.
- [x] Elimination-is-final rule — **decided at implementation time (2026-08-20): elimination is instantly, unconditionally final**, no rescue-by-later-breeding-pick mechanic. The already-shipped Phase 3 behavior (ending the run the instant the player is last-placed) needed no changes. A literal reading of GDD §6.6's "and isn't chosen... as a breeding partner" clause would have required continuing to silently simulate the player's former group after elimination — considered and explicitly rejected in favor of the simpler behavior.
- [x] Scoring: unchanged from Phase 3 (`playerScore` already accumulates 6/5/4/3/2/1 across every race, including the Final Race) — no new work needed here either.
- [x] Next-Tournament generation (`prepareNextTournament`): always exactly 3 lineage babies (one per finalist, one shared name-draw across all 24 upcoming entrants so nothing collides) + 21 freshly random, every time.
- [x] **Decided at implementation time: the player plays as their own baby.** If the player reaches the Final Race and breeds, their baby (not a blank Chao) becomes their starting point for the next Tournament — inherited stats, then a fresh Draft Booster and bonding on top of that baseline. The other 2 finalists' babies become NPC lineage entrants among the 23 others. `createTournament` gained an optional `others` parameter (a pre-built 23-entrant roster) for this; Tournament 1 still generates all 23 procedurally when omitted.
- [x] App: new `BreedingScreen.tsx` — partner picker (click-to-select from the eligible pool, with scouting reads) → confirm → a Breeding Results summary for all 3 pairings → "Start Next Tournament", which resets `draft`/`environment`/pool state and kicks off a fresh Draft Booster with the player's baby as the starting Chao.
- [ ] **Deferred, not part of this phase's "done" (decided 2026-08-20, same pattern as Phase 4's race-reward hooks):** the full Chao inspection/lineage UI (GDD §6.8) — Name/Height/Weight/Record on any entrant, "raced this Chao"/"raced its predecessors" indicators, a Lineage tab. Needs new persisted per-Chao history and a real parent-A/parent-B graph, neither of which exist yet — a substantial follow-up on its own, and not required by this phase's completion bar.

## Phase 5.5 — Bond Cards one-time use, Awakening, and real per-race timing/results *(complete, 2026-08-20)*

Requested directly by the user after playing the Phase 5 build and asking two pointed questions: "is there any legitimate UI for race results, or just a rolling log entry?" (no) and "are bonded cards one-time use?" (no, and they should be). Not originally scoped as its own phase — Awakening was already a Phase 6 item; the other two are corrections/additions that came out of that conversation.

- [x] **Bond Cards are now one-time use.** Bonding a specific drafted copy consumes it — `useGame.ts` tracks `usedPoolIndices` (a `Set<number>` of positions in the combined pool, since duplicate copies of "the same" card share an `id` and can't be told apart by id alone) and `GardenScreen.tsx` only ever renders still-unused copies. This is a real behavior change from every prior phase, where a single drafted Bond Card could be re-clicked and re-bonded indefinitely.
- [x] Implemented Awakening (GDD §4.6) at the same time, since it's the *other* thing you can do with a Bond Card copy instead of spending it alone: `chao/bonding.ts`'s `awakenBondCard()` fuses 3 unused copies of the same card into one enhanced application — **3.5× a single copy's AVERAGE stat grant** ((min+max)/2 × 3.5), fully deterministic (no grade roll, no rng), producing exactly one `BondedCard` history entry flagged `awakened: true`. `GardenScreen.tsx` shows an "Awakening Available" option whenever 3+ unused copies of one card exist.
- [x] **A real per-race Results screen** (`RaceResultsScreen.tsx`) replacing "check the rolling log" as the only way to see how a race went: a ranked table (1st through last) with each Chao's **total time and a per-Leg time breakdown, to the tenth of a second**, fumbled Legs highlighted, the eliminated entrant marked — shown as a full-screen overlay (`useGame.ts`'s `raceResult` state takes priority over whatever `phase` is underneath) after every group race and the Final Race, dismissed with a "Continue" button. The scrolling Event Log still exists alongside it for full narration history; the Results screen is the new "what just happened, clearly" answer.
- [x] New `packages/sim/src/events/timing.ts`: `computeRaceTiming()`, a **display-only** computation over an already-resolved race's `leg_result` events (extended with new `stat`/`difficulty` fields specifically to support this) — it does not feed back into pass/fail, DNF, elimination, scoring, or ranking, all of which are exactly the same stat-check/Stamina mechanics as every prior phase. Calibrated against the user's own reference point: a brand-new, near-zero-stat Gen-1 baby should average ~9.0 seconds/Leg regardless of course length (5 Legs in ~45s, 10 Legs in ~90s) — verified this holds via a real calculation, not just an assumption: a 0-stat Chao can never clear 15-30 Leg difficulty against only ±5 variance, so it fumbles every Leg, and the fumble penalty had to be folded into that 9.0s baseline rather than sitting on top of it (a real calibration mistake caught and fixed before this shipped).

**Done when:** ✅ Met — `pnpm build`/`typecheck`/`test` all green (126 sim tests, up from 119: +7 new across `chao/bonding.test.ts`'s `awakenBondCard` tests and the new `events/timing.test.ts`). Verified live via Playwright: bonding a card removes it from the Bond Cards grid immediately (confirmed a card present at count 13 dropped the grid to 12, with 0 remaining copies of that exact card); an "Awakening Available" option appeared for a 3-copy stack and, on click, fused all 3 into one `★`-flagged Bonding History entry with the exact expected math (Glassfin Guppy's fly grant, avg 8 × 3.5 = 28, matched precisely in the log); and the Race Results screen renders a full ranked table with per-Leg times to the tenth of a second, the eliminated entrant struck through, fumbled Legs colored, and a working "Continue" button — confirmed clean at both a wide viewport and the default ~1280px width (no horizontal page overflow; the table scrolls in its own container). Zero console errors throughout.

## Phase 7 — Stretch / post-MVP

1. **Entrant generation v2** (GDD §6.7, written up 2026-08-20): each non-player entrant runs its own mini-draft (existing `draft/bots.ts` heuristic) plus a new bot-bonding heuristic that doesn't exist yet (greedily bond highest-`rawPower` card per slot). Upgrade path from Phase 3's v1 procedural roll, once the core loop is proven and playtesting shows the bracket feels hollow.
2. **Full off-path bracket visibility** (GDD §6.7, written up 2026-08-20): let the player actually watch (not just scout) other groups' races, full event-log playback — not just a final ranking. Upgrade path from Phase 3's "own path only" scope.
3. **Multiplayer live co-draft** (architecture.md §9) — network-backed draft seat for the (now-confirmed-surviving) pack-passing Draft Booster.
4. **Async Tournament entrants** (architecture.md §9) — real players' saved Chao lineages filling non-player bracket slots, replacing (or supplementing) procedural generation. A natural extension of entrant generation v2 above.
5. **Cosmetic-only long-term unlock track** (was GDD §7.6's "Difficulty Rank," survives as a stretch idea even though the rest of that section was cut).
6. **Larger card-set expansion** (was Phase 4's target — 180–220 cards recommended, revisit once real repeat-Tournament data exists).
7. **A Kindergarten-style narrative event** — the user likes the idea but confirmed (2026-08-20) it's **unneeded in the design right now**; kept as a TODO to consider later, not an active open question. See the explanation below the open-questions table for what it was and the options for where it could go, whenever it's picked back up.
8. **Rolling lineage from the eliminated/losing pool** (GDD §6.5, written up 2026-08-20): letting Gen 2 through Gen X draw on non-finalist eliminated Chao too, not just the 3 breeding finalists' babies — a genuine "rolling lineage" upgrade over the simple 3-and-21 split. Explicitly deferred by the user, not built now.

**What Kindergarten actually was, for context:** in the source material, the Kindergarten is a passive training location distinct from active feeding — a schoolhouse where a Chao learns instruments and other lessons, gated by (and raising) its Mind stat. The original pre-pivot GDD turned this into a "?"-style narrative map node with Mind-gated outcomes. That map is gone now, so Kindergarten has no home — three real options, none chosen yet: **(1)** fold an occasional narrative choice into an Environment Interlude alongside the booster draft; **(2)** give it its own new Interlude-adjacent moment; **(3)** cut it entirely, since nothing else in the Tournament structure obviously needs a Mind-gated narrative event to exist. Whichever way this goes, the actual *content* (a real pool of written vignettes) was always deferred content-pass work regardless — "what does Kindergarten do" and "what does Kindergarten say" are two separate open items.

## Trademark & naming

"Chao," "Chaos Drive," "Chao Garden," and related terms belong to SEGA. This entire doc set uses them because that's the clearest way to specify *what's being cloned* during design — not because they're intended to ship. Before any build leaves personal/prototype use:

- [ ] Rename the creature (currently "Chao") to an original name across code, assets, and docs.
- [ ] Rename "Chaos Drive" → the Regimen Card flavor text/naming already mostly stands on its own (GDD §4.2) and doesn't need "Chaos Drive" as a literal in-game term — audit for stray references.
- [ ] Rename "Chao Garden," "Chao Race," "Jewel Cup" — SEGA-specific proper nouns, even though the *mechanics* they name are being reinterpreted, not copied wholesale. ("Chao Karate" no longer needs renaming — it's removed rather than kept under a new name.)
- [ ] Original visual design for creature bodies/mutations — do not reference or trace SEGA's Chao model/art.
- [ ] Legal review of the final name/branding before any public distribution (storefront listing, trailer, itch.io page, etc.) — this checklist is a starting point, not a substitute for that.
